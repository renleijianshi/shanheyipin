# REQUIREMENTS

## 当前有效范围

- 微信小程序、Web 管理后台、API、MySQL/Redis、对象存储、供应链/库存、会员营销、内容溯源和企业团购。
- 按 `tasks/M01` 至 `M46` 增量交付，每个模块独立分支、测试、Review、PR。

## 业务硬规则

- 金额统一使用整数分；服务端计算订单金额。
- SPU、SKU、库存批次分别建模；订单保存商品快照。
- 商品分类使用稳定唯一代码和父子树；小程序只展示启用分类，禁用父分类隐藏其整个子树。
- 库存由余额、流水、批次共同构成；取消/超时释放锁定库存。
- 包装必须使用 BOM、加工任务、领料、损耗和成品批次。
- 售后区分仅退款、退货退款、补发、赔付；退货质检后才决定库存去向。
- 预售与现货库存隔离；关键后台操作保留审计记录。

## 支付阶段要求

- Real WeChat Pay = Deferred。
- Real Alipay = Deferred。
- 不索取任何微信/支付宝商户密钥、证书或商户资料。
- 先实现 `PaymentProvider`、`PaymentOrder`、状态机、幂等、回调接口、配置占位、`MockPaymentProvider`、`DisabledPaymentProvider`、单元测试和集成测试。
- 不做真实支付、真实退款、正式商户回调联调。
- 使用 Mock/Disabled Provider 跑通订单、库存、售后链路。

## 运行与部署约束

- 新 API：`127.0.0.1:3200`。
- Redis：`127.0.0.1:6379`，内存限制 64-128MB。
- 服务器资源：2 vCPU、1.6 GiB RAM、2 GiB Swap、40GB。
- 不触碰旧 `/opt/shanhe-yipin`、3000 端口或既有服务。
- 未经确认不执行正式发布或不可逆生产操作。
