# 山禾颐品小程序 PRD

## 1. 背景

山禾颐品以甘肃舟曲吊柿/柿饼作为首发产品，通过产地、非遗工艺、东方审美包装和精选逻辑建立品牌信任，后续扩展为“西北精选农特好物”品牌。

小程序需要解决当前业务的几个关键痛点：

- 社媒负责种草，但缺少统一成交阵地；
- 产地故事、非遗工艺与商品交易分离；
- 精品、普通、礼盒、袋装、试吃装 SKU 容易混乱；
- 农产品存在批次、等级、损耗、霉变/破损等问题；
- 预售与现货并存；
- 企业客户需要批量采购；
- 包装精致，但需要数字化溯源进一步提升信任；
- 后台不能只管订单，还要能管理采购与库存。

---

## 2. 目标

### 2.1 商业目标

- 建立品牌私域成交入口；
- 提升从内容到购买的转化；
- 降低预售和库存错配风险；
- 支持个人消费者和企业礼品两类订单；
- 建立可复用的农特产品供应链数字化底座。

### 2.2 产品目标

用户能在 3 分钟内完成：
`种草内容 → 看懂产品 → 选规格 → 下单 → 微信支付`

运营能完成：
`建商品 → 配活动 → 上架 → 看订单 → 发货 → 售后 → 看数据`

仓库能完成：
`采购收货 → 质检 → 批次入库 → 分级 → 包装加工 → 锁库存 → 拣货 → 出库 → 盘点 → 损耗`

## 4. 典型用户场景

### 场景 A：抖音/小红书种草后购买

用户看到“舟曲吊柿”内容 → 搜品牌/扫码 → 小程序首页 → 商品详情 → 了解产地/工艺 → 选择礼盒 → 下单支付。

### 场景 B：春节送礼

用户进入“节礼专区” → 根据预算筛选 → 选择礼盒 → 填写收货地址/赠言 → 微信支付 → 订阅发货通知。

### 场景 C：预售

用户看到“本季首批预售” → 查看预计发货日期、预售规则 → 支付 → 系统记录预售批次 → 到货后按批次出库。

### 场景 D：扫码溯源

收礼者扫描盒上二维码 → 查看该盒商品批次、产地、工艺、装盒日期、建议食用方式；高阶版本可查看该盒对应装盒短视频。

### 场景 E：企业礼品

企业采购 → 企业团购页 → 选择预算、数量、开票/定制需求 → 提交询价 → 后台生成线索 → 人工报价 → 后续形成企业订单。

### 场景 F：售后

用户订单详情 → 申请售后 → 选择破损/品质/少件/物流等原因 → 上传图片 → 客服审核 → 退款/部分退款/补发/优惠券补偿。

## 5. 商品体系

建议把“商品 SPU”“销售规格 SKU”“库存批次”分开。

示例：

**SPU：舟曲吊柿**

SKU：
- 精品透明盒 8 枚；
- 精品双层礼盒 16 枚；
- 春节四层礼盒 28 枚；
- 普通袋装 1 斤；
- 普通袋装 2 斤；
- 试吃装 4–6 枚。

同一 SKU 可由不同采购批次生产，但出库需要记录实际使用批次。

## 7. 非功能需求

### 性能

- 首页核心接口 P95 < 500ms（不含第三方服务）；
- 商品详情 P95 < 500ms；
- 下单写操作优先保证正确性；
- 图片全部 CDN/对象存储；
- 支持后续水平扩容。

### 可用性

- 核心交易服务目标 99.9%；
- 微信支付回调可重复处理；
- 订单、库存、退款操作有重试策略；
- 数据每日自动备份。

### 安全

- 不在前端保存任何商户密钥；
- 微信支付私钥仅服务器保存；
- API 鉴权；
- 管理后台 RBAC；
- 数据权限；
- 防重复提交；
- 防刷券；
- 限流；
- 敏感日志脱敏。
