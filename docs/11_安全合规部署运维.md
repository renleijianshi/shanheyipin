# 安全、合规、部署与运维

## 1. 小程序与账号

上线前需要准备并核实：
- 微信小程序主体；
- 小程序类目；
- 域名；
- HTTPS；
- 服务器域名白名单；
- 微信支付商户；
- 隐私保护相关配置；
- 用户协议；
- 订阅消息模板；
- 交易发货相关能力。

具体要求以上线时微信官方平台最新规则为准。

---

## 2. 隐私

遵循“最少收集”。

可能涉及：
- 微信用户标识；
- 手机号；
- 收货人；
- 电话；
- 地址；
- 售后图片；
- 企业联系人资料。

要求：
- 明确用途；
- 权限最小化；
- 敏感字段加密/脱敏；
- 日志中不打印完整手机号/地址；
- 提供账户注销路径；
- 数据留存策略。

---

## 3. 支付安全

- API v3 相关密钥仅服务器保存；
- 证书/私钥不进 Git；
- 支付回调验签；
- 金额二次校验；
- 商户订单号唯一；
- 退款权限严格控制；
- 财务对账。

---

## 4. 后台安全

- 管理员强密码；
- 登录失败限流；
- 可选 MFA；
- RBAC；
- IP 白名单可选；
- 敏感操作二次确认；
- 操作日志；
- 导出审计；
- 离职账号及时禁用。

---

## 5. 应用安全

- 输入校验；
- 输出转义；
- CSRF（后台 Web 认证模式决定）；
- XSS；
- SSRF；
- 文件上传验证；
- URL 白名单；
- SQL 参数化；
- API 限流；
- 防重复提交；
- CORS 白名单；
- 依赖漏洞扫描。

---

## 6. 数据备份

最低要求：
- MySQL 每日自动备份；
- 保留至少 7–30 日；
- 重要版本发布前手动快照；
- 定期恢复演练；
- OSS 开版本控制或生命周期策略。

不能只有“有备份”，必须验证“能恢复”。

---

## 7. 日志

分类：
- 应用日志；
- API 访问日志；
- 错误日志；
- 支付日志；
- 定时任务日志；
- 管理员操作日志；
- 登录日志；
- 库存流水；
- 财务流水。

使用 requestId 串联请求。

---

## 8. 监控

首期：
- CPU；
- 内存；
- 磁盘；
- MySQL；
- Redis；
- HTTP 5xx；
- API P95；
- 支付回调异常；
- 定时任务失败；
- 数据库备份失败。

---

## 9. 发布

建议：

```text
feature branch
→ Pull Request
→ 自动测试
→ staging
→ 人工验收
→ 数据库备份
→ production
→ 冒烟测试
→ 监控
```

数据库变更使用 migration，不允许直接在生产库手工改结构。

---

## 10. 容灾

首期至少做到：
- 可重新部署应用；
- 数据库可从备份恢复；
- 对象存储不与应用服务器同盘；
- 配置和密钥有安全备份；
- 支付/库存关键任务可重放。

---

## 11. 食品与商品信息

系统应预留：
- 产地；
- 净含量；
- 保存方式；
- 保质/建议食用期；
- 生产者/供应来源；
- 批次；
- 检测/质检附件；
- 商品标签图片。

具体商品标签、食品/初级农产品销售资质与宣传措辞应在实际上线前按商品实际加工、包装和销售方式做合规确认。
