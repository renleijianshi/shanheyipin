## 2. 开发规则

- 未确认文档前，不直接大规模生成代码；
- 先生成项目计划；
- 按模块开发；
- 每完成一个模块更新进度；
- 数据库 schema 先评审再 migration；
- 支付、库存、退款先写测试；
- 不允许把密钥写入代码；
- 不允许跳过权限；
- 不允许为了“跑起来”而删除关键校验；
- 不允许直接手工修改生产库存；
- 不允许在业务代码中硬编码商品 ID、活动 ID。

## 6. 禁止一次性生成整个项目

推荐顺序：

```text
基础工程
→ 用户登录
→ 商品
→ 购物车
→ 订单
→ 微信支付
→ 库存
→ 发货
→ 售后
→ 采购
→ 批次
→ 加工
→ 营销
→ 内容
→ 溯源
→ 企业团购
→ 报表
```

每一步可运行、可测试、可提交。

---

## 7. 关键技术决策（ADR）

后续重要改动必须记录在：

```text
docs/adr/
```

例如：
- ADR-001 为什么选 NestJS；
- ADR-002 为什么库存采用批次流水；
- ADR-003 为什么第一期不用微服务；
- ADR-004 为什么预售全款而非定金；
- ADR-005 二维码一批一码升级一盒一码方案。

这样即使换 AI、换开发者，也能理解“为什么这么做”。
