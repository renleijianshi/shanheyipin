# 测试、验收与里程碑

## 1. 测试层级

### 单元测试
重点：
- 价格计算；
- 优惠；
- 库存；
- 订单状态；
- 退款；
- 积分；
- 批次转换。

### 集成测试
- 微信登录；
- 微信支付；
- 支付回调；
- 退款；
- 对象存储；
- 物流。

### E2E
完整路径：
`登录 → 商品 → 加购 → 结算 → 下单 → 支付 → 后台发货 → 收货 → 售后`

---

## 2. 必测边界

- 最后一件库存同时下单；
- 重复点击提交订单；
- 微信支付回调重复 10 次；
- 支付成功但小程序没收到结果；
- 订单超时与支付回调同时发生；
- 优惠券刚好过期；
- 退款重复回调；
- 退货后库存处置；
- 同一批次发生盘点和出库冲突；
- 预售超卖；
- 多件商品部分售后；
- 补发；
- 企业多地址；
- 二维码重复扫描。

---

## 3. 性能测试

首期目标参考：
- 100–300 并发用户即可覆盖初期大部分活动场景；
- 支付/下单重点压测；
- 后台导出异步；
- 图片不走业务服务器。

活动前根据粉丝量和投放量重新估算。

- 库存正确；
- 优惠正确；

- 可发货；
- 可退款；

- 可查库存流水；
- 可盘点；

## 6. 第一版建议不上线的复杂能力

为了避免项目失控，第一版不优先：
- 多商户；
- 多租户 SaaS；
- 微服务；
- 分布式数据库；
- 复杂分销；
- 直播；
- 秒杀集群；
- 定金预售；
- 完整会计系统；
- 自建即时通讯；
- 自动化仓储设备。

数据模型留扩展点即可。
