# 山禾颐品测试驱动开发

1. 查看 `package.json`、对应测试和实现，沿用本项目 Vitest、TypeScript 和依赖注入约定。
2. 对新逻辑先写能表达预期行为的测试；修 Bug 时先写能复现问题的回归测试。
3. 运行单个目标测试确认测试覆盖了目标行为，再写最少实现让其通过。
4. 补足失败路径、边界条件和关键幂等/并发条件；不要测试私有实现细节。
5. 重构后重跑目标测试。交付前运行任务要求的 lint、typecheck、test 和 build。

金额使用整数分。订单、支付、退款和库存逻辑需覆盖金额/归属校验、幂等及事务一致性；具体覆盖范围按对应任务卡确定。不要为了让测试通过而删除业务校验。
