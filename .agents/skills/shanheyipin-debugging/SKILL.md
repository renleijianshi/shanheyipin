# 山禾颐品系统化排错

1. 记录可复现步骤、完整错误和受影响模块；先看 `git status`、相关 diff 和最近提交。
2. 用错误信息搜索相关代码，只沿当前调用链读取文件；多层系统按页面/适配器/API/service/repository/schema 分界定位。
3. 检查当前分支、配置、依赖、Prisma schema 和迁移是否与预期一致；不要把网络、环境错误误判为代码错误。
4. 先添加或运行能重现问题的最小测试，确认故障位置后再修复。
5. 保持修复范围最小；重跑回归测试和相关质量检查，并检查 diff 中无无关改动。

连续修复失败时不要继续猜测；总结已验证证据与唯一未解决的问题，再决定是否需要用户提供外部环境信息。
